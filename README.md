# CZSC 结构监控项目

**当前基线：v0.11.0**

这是一个面向 Binance K 线的 CZSC（缠论结构）监控与验证项目。主流程覆盖：

```text
原始 K 线
→ 去包含
→ 分型
→ 笔
→ 标准特征序列线段
→ 笔中枢 / 线段中枢
→ 单级别 B1 / B2 / B3 与 S1 / S2 / S3
→ 候选层与正式层分离
```

当前版本优先解决两个问题：第一，正式结构和买卖点必须可审计、可复现、不能提前确认；第二，买卖点级别语义必须明确，不能把当前周期内部的笔伪装成真实低级别递归结构。

## v0.11.0：当前生产买卖点是单级别模式

当前生产路径明确采用**单级别线段中枢买卖点**：

```text
当前周期 K 线
→ 当前周期笔
→ 当前周期正式线段
→ 当前周期正式线段中枢
→ 当前周期 B1 / B2 / B3、S1 / S2 / S3
```

判断正式买卖点时，只使用：

- 当前周期已经正式提交的线段；
- 当前周期正式线段中枢；
- 当前周期线段之间的价格结构；
- 当前周期对应 K 线的精确 MACD 状态；
- 正式线段的真实 `committed_at` 与结构 fingerprint。

**当前周期线段内部的 `segment.strokes` 不再被当作“次级别”。** 因此，一个 5m 线段内部即使由若干 5m 笔组成，也不会被解释成真实 1m 结构。真实 1m→5m、5m→30m 等递归确认属于后续独立阶段，届时必须显式输入真实低级别 `AnalysisResult`。

### B1 / S1

B1 的当前规则：

1. 至少存在两个连续正式线段中枢；
2. 两个中枢满足严格向下趋势关系；
3. 同级连接段 `b` 与最后中枢最终离开段 `c` 都向下；
4. `c` 创出本次趋势新低；
5. MACD 状态必须来自真实历史起点，或由合法 `MacdAnchor` 精确续算；
6. `c` 的负柱面积小于 `b` 的负柱面积，形成同方向 MACD 背驰；
7. 信号确认时间不得早于 `c` 的正式提交时间。

S1 完全镜像。

这一阶段**不要求** `c` 内部再形成笔级三买/三卖，也不要求 `c` 内部至少存在两个笔中枢。

### B2 / S2

B2 必须建立在已经正式确认的 B1 上：

1. B1 后紧随一条本级别向上反弹线段；
2. 下一条正式线段是第一次向下回试；
3. 第一次回试终点不得跌破 B1 低点，允许等价触碰；
4. 确认时间使用该回试线段的真实正式提交时间。

S2 完全镜像。

这一阶段**不要求**回试线段内部再出现笔级 B1 / S1。

### B3 / S3

B3 保持线段中枢的单级别定义：

1. 一条正式线段向上离开固定线段中枢；
2. 紧随其后的第一条反向正式线段是第一次回试；
3. 回试最低点不重新进入中枢，即 `low >= ZG`，边界触碰允许；
4. 确认时间使用回试线段正式提交时间。

S3 镜像为向下离开后第一次向上回试，要求 `high <= ZD`。

## 正式层与候选层

项目明确区分“当前检测结果”和“可以被下游消费的正式结果”。

```text
detected_strokes           当前笔检测结果，允许尾部变化
all_strokes                当前接受的完整笔链
stable_strokes             已封存、只增不减的稳定笔前缀
provisional_strokes        仍可能迁移或撤销的尾部笔

detected_segments          当前窗口直接识别出的线段
unresolved_prefix_segments 左边界尚未解析时的候选线段
segments                   已正式提交的线段账本
provisional_segments       尚未提交的右侧候选线段
```

正式买卖点只消费具有可信左边界、稳定右边界和完整提交证据的结构。

### 左边界

任意有限历史窗口本身不能证明绝对线段相位。因此默认：

```text
没有真实历史起点声明，也没有持久化 StructureAnchor
→ 可以计算候选笔和候选线段
→ 不发布正式线段、中枢和买卖点
```

调用方只有在能够证明数据从真实历史起点开始时，才应显式使用：

```python
result = analyze_bars(
    bars,
    left_boundary_anchored=True,
)
```

生产滚动窗口更推荐恢复持久化 `StructureAnchor`。

### 右边界

正式线段采用两阶段提交：

```text
DETECTED
   │ 后续结构提供足够确认
   ▼
COMMITTED
```

当前最后一条已检测线段可以继续变化；只有进入 `segments` 的正式线段才允许被正式中枢、买卖点、通知和回测消费。

## MACD 状态与身份绑定

滚动窗口不能从窗口首价重新初始化 EMA 后再把结果当作精确历史。正式 B1 / S1 需要：

- 从真实历史起点递推 MACD；或
- 使用可以精确连接当前窗口的持久化 `MacdAnchor`。

锚点绑定 `symbol`、`interval`、上一根 K 的时间游标和内容指纹、历史起点、累计处理数量及 `exact` 状态。品种、周期、时间连续性或内容身份任一不匹配时，正式一类点 fail closed。

## K 线与正式证据安全约束

v0.10.17 引入并在 v0.11.0 保留的安全约束包括：

- 单根 K 线也必须通过周期合法性校验；
- K 线 `close_time` 不得越过下一周期起点；
- `MacdAnchor.expected_next_open_time` 必须能够由 `last_open_time + interval` 唯一推导；
- `MacdAnchor.last_close_time` 不得越过下一周期起点；
- `SegmentEvidence`、正式提交时间和结构 fingerprint 强绑定；
- 缺少任何正式线段提交证据时，正式买卖点接口直接安全关闭，不使用端点时间兜底。

## 数据与刷新

Streamlit 默认配置：

```text
数据源：Binance
交易对：BTCUSDT
周期：5m
已收盘历史：5000 根
实时未收盘：最多 1 根
```

首次加载分页获取历史数据，之后使用增量 REST 轮询。当前未收盘 K 与已收盘历史严格分离；当前 K 更新只影响 live / provisional 展示；新 K 收盘后才推进 confirmed 分析。请求失败时保留上一份完整快照，不让半截数据进入正式分析。

当前 UI 不是逐 tick 交易终端，也没有后台常驻 WebSocket 守护进程。

## 图表语义

- 稳定笔和正式线段：实线；
- 候选笔和候选线段：同色虚线；
- 当前未收盘 K：独立实时层；
- 图层颜色、粗细、透明度和 hover 设置只影响展示，不进入算法判断。

候选结构允许迁移、替换或消失，不参与正式中枢和正式买卖点计算。

## 验证

正式发布以当前 PR 的 Python 3.10、3.11、3.12、3.13 GitHub Actions 全矩阵为门槛。单级别买卖点专项测试包含：

- 每条线段只有一笔时仍能识别合法 B1 / B2、S1 / S2；
- B2 第一次回试跌破 B1 极值时必须拒绝；
- B3 / S3 允许准确触碰中枢边界；
- 缺少正式提交证据时 fail closed；
- MACD 历史不精确时 B1 / S1 只能保留候选；
- 生产公开 API 和增量/批量分析都必须路由到单级别 detector。

完整验证入口、脚本与判定原则见 [`VALIDATION.md`](VALIDATION.md)。

## 当前阶段边界

- 当前生产买卖点已经是单级别线段中枢模式；
- 尚未实现真实跨周期递归买点确认；
- 尚未提供后台常驻进程、数据库、WebSocket 守护和消息通知服务；
- 后续任何通知都必须只使用正式结构及真实 `confirmed_at_dt`；
- 下一阶段递归实现必须显式引入真实低级别数据，不允许恢复“用本级别内部笔代替低级别”的做法。
