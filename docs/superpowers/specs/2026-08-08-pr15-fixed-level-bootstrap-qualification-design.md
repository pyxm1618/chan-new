# PR #15 Fixed-Level Bootstrap Qualification Closure

Date: 2026-08-08
Branch: `agent/fixed-level-bootstrap-qualification`
Base: `agent/single-level-trading-points` (PR #13)

## Goal

Close the remaining qualification gaps in PR #15 without changing PR #14, without adding trading-point strength profiles, and without widening the scope beyond the Lesson 57 fixed-level bootstrap qualification of PR #13.

The PR is complete only when the fixed-level production path accepts only formally confirmed Chan Segments, uses Lesson 78 actual segment intervals for SegmentCentralZone calculations, implements the Lesson 67/77 second-case reverse feature-sequence rule, and the full supported test matrix is green.

## Non-goals

- No long-term recursive MovementType architecture implementation.
- No B1/B2/B3 strength or profile configuration.
- No replacement of the PR #13 single-level trading-point formulas beyond qualification boundaries required by this audit.
- No reintroduction of same-interval internal strokes as fake lower-level trading-point evidence.
- No rollback of the Lesson 78 actual Segment interval semantics to satisfy legacy fixtures.

## Chosen approach

Use the existing segment detector/evidence model as the source of formal provenance instead of duplicating the feature-sequence algorithm inside the trading-point wrapper.

Rejected alternatives:

1. Re-run the full Segment detector inside `formal_single_level_trading_points.py` for every supplied Segment chain. This duplicates algorithm ownership and risks future divergence.
2. Keep accepting arbitrary hand-built odd-stroke Segments plus a caller-provided commit-time mapping. This proves only local geometry and does not prove formal feature-sequence provenance.

The selected design keeps local structural fail-closed checks as cheap defensive validation, but formal eligibility additionally requires identity-bound committed `SegmentEvidence` generated by the Segment engine/ledger.

## Design

### 1. Lesson 67/77 second-case reverse feature sequence

The primary feature-sequence detector continues to require the current actual-break semantics.

The reverse/second feature sequence used to resolve the second case must not recursively require the primary first/second-case actual-break confirmation again. It must still use standard feature-element inclusion handling and require a valid standard feature-sequence fractal, but that fractal itself is sufficient for the reverse confirmation.

Implementation intent:

- Keep `_FeatureDetector(require_actual_break=True)` for the primary sequence.
- Construct the second/reverse feature-sequence detector with `require_actual_break=False` in the second-case path.
- Preserve all existing inclusion processing and endpoint identity rules.
- Keep the golden regression where the standard reverse fractal exists while the generic primary actual-break state remains `PENDING`; the reverse attempt must nevertheless confirm.

### 2. Formal Segment provenance

`formal_single_level_trading_points.detect_trading_points()` and `validate_trading_points()` must fail closed unless every participating Segment has formal, identity-bound, committed evidence.

Required conditions for each Segment:

- local Segment structure remains intrinsically valid;
- a corresponding `SegmentEvidence` exists;
- `evidence.matches_segment(segment)` is true;
- `evidence.is_committed` is true (`committed_at` is present);
- evidence ordering/count is compatible with the Segment chain;
- callers cannot obtain formal status merely by supplying a `segment_commit_times` dictionary for a hand-built Segment.

The existing `SegmentEvidence` object remains the provenance authority. No duplicate feature-sequence implementation will be added to the formal trading-point module.

Compatibility policy:

- The internal/raw single-level detector may retain lower-level compatibility hooks needed by historical tests.
- The public formal production entry point must require formal evidence.
- Commit time used downstream should be derived from or checked against the committed evidence rather than treated as an independent credential.

### 3. Real detector integration

Add an end-to-end qualification test that starts from a Stroke chain, calls `detect_segments()`, obtains the detector's `SegmentEvidence`, turns that evidence into committed evidence using the same immutable Segment identity, and then passes the resulting Segment chain/evidence into the formal trading-point path.

The test must demonstrate:

- real detector output is accepted;
- a structurally plausible hand-built Segment without committed matching evidence is rejected;
- mismatched fingerprint/symbol/interval evidence is rejected;
- uncommitted evidence is rejected;
- a forged commit-time mapping alone cannot bypass provenance.

### 4. Lesson 78 Segment actual interval and independent reference

Keep production `Segment.high` / `Segment.low` as the extrema across internal Strokes. Keep `endpoint_high` / `endpoint_low` for formal endpoint geometry.

Update `segment_central_zone_reference.py` so its frozen oracle independently recomputes each Segment's actual price interval from `segment.strokes`, rather than using endpoint values and rather than delegating to the production `Segment.high` / `Segment.low` properties.

This preserves differential-test independence while aligning the oracle with the corrected Lesson 78 semantics.

### 5. Fixture migration

Legacy fixtures that depended on `Segment interval == formal endpoint interval` must be rebuilt so their intended structures remain valid under actual internal ranges.

Rules for fixture changes:

- Do not weaken production theory rules just to restore old expected outputs.
- Each synthetic Segment must contain at least three alternating Strokes with coherent shared endpoints.
- Trading-point fixtures must intentionally produce the requested SegmentCentralZone/trend/B1/B2/B3 geometry under actual-range semantics.
- Where practical, prefer detector-produced Segments over manually constructed ones for formal-path tests.

### 6. Validation and completion criteria

PR #15 remains Draft until all of the following hold on one final head commit:

1. Default pen spacing tests demonstrate original-theory default `min_bi_len=7` and explicit compatibility `min_bi_len=6`.
2. Lesson 78 Segment actual-range tests pass.
3. Lesson 67/77 second-case golden test passes because production reverse logic is corrected, not because the fixture is weakened to satisfy primary actual-break semantics.
4. Formal detector provenance tests pass for accepted real evidence and all fail-closed cases.
5. SegmentCentralZone frozen-reference differential tests pass using independently computed actual ranges.
6. Existing single-level B1/B2/B3 and S1/S2/S3 contract tests pass with valid >=3-stroke Segment fixtures.
7. Real `detect_segments()` -> committed evidence -> SegmentCentralZone -> formal trading-point qualification integration passes.
8. Full GitHub Actions Python 3.10, 3.11, 3.12, and 3.13 matrix is green.

Only after those conditions are satisfied should PR #15 move from Draft to Ready for Review and PR #13 receive a Lesson 57 fixed-level bootstrap qualification PASS.

## Error handling

Formal qualification failures remain fail-closed and return explicit diagnostics rather than falling back to permissive single-level behavior. Provenance failures should use distinct diagnostic codes for missing, uncommitted, and identity-mismatched evidence so tests and runtime auditing can distinguish them.

## Scope guard

Any failure discovered while implementing this spec that belongs to strength scoring, recursive MovementType construction, cross-level trading-point constitution, or PR #14 architecture is recorded separately and is not fixed in PR #15 unless it directly prevents the qualification invariants above from being true.
